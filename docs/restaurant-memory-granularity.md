# Restaurant memory answer granularity

Canonical restaurant notes are Obsidian-authoritative and read-only at answer time.

- **Broad venue questions** retain the complete selected restaurant parent within the configured context budget. Answers should summarize all materially useful recorded facts: household preferences, shared dishes/guidance, and visit history.
- **Requester-specific broad questions** lead with the requester’s facts, then include concise, clearly attributed facts for other household members.
- **Narrow dish/person/usual-order questions** may scope the answer to the requested predicate. Evidence retains shared ancestor sections for provenance, but synthesis should answer only the requested fact.
- “No usual order recorded” is not equivalent to “no likes or history recorded.” Unknown and explicit negative facts must remain distinct.
- Reciprocal dish evidence is line-scoped to the selected venue to prevent cross-venue bleed.

Authorization, canonical-path admission, and requester visibility rules are unchanged.
